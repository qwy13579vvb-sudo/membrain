# 设计取舍与踩过的坑

这份文档记的是「为什么这样设计」，以及真机（Android 手机 + Node 24）上踩过的坑。

---

## 一、为什么是 SQLite，不是向量数据库

- 单机、单用户、几千到几十万条 —— SQLite + FTS5 完全够，且**零运维**
- 向量用「中文 2-gram 哈希」（256 维），不依赖任何 embedding 服务
- 检索：副库（id/标签/片段）先定位 → 主库取正文，**避免全表扫描**
- 实测 900+ 条、副库 200KB，检索 7–30ms

**代价**：语义检索弱于真向量模型。补偿手段是多路召回 + 图扩展 + 标签。

---

## 二、为什么要有「副库」

主库 9.8MB，每轮都读会慢。副库只存：
`id / 标签 / 60 字片段 / 权重 / 时间` —— 208KB，可以直接 JSON.parse 进内存。

流程：`locate()`（副库匹配）→ `fetchFull()`（主库取正文）→ 重排 → 预算裁剪。

---

## 三、遗忘曲线为什么用「强度 S」而不是「固定半衰期」

固定半衰期会让所有记忆一起淡掉，而人不是这样：**重要的、反复想起的、情绪强烈的，掉得慢**。

```
S0 = (3 + 17×(0.5×重要度 + 0.3×唤醒度 + 0.2×|情绪|)) × 层级倍率
```

层级倍率 `{L1:1, L2:1.6, L3:2.6, L4:6}`：抽象层本来就该活得更久。

---

## 四、为什么要「睡眠重放」

后台不重放的话，只有被真实检索到的记忆才会变强 —— 那些重要但从没被问到的会慢慢死掉。
重放（k=0.35）模拟海马体：**不替代真实回忆，只是减缓衰亡**。

---

## 五、替代链（supersede）为什么必要

没有它，库里会同时存在「我要用 A 方案」和「我改用 B 方案」，检索出来自相矛盾。

```
同话题         → 直接判替代
同类型 相似≥0.90 → 判替代
跨类型 相似≥0.97 → 判替代
只认最近的一条新版（避免 A→B→C 乱串）
```

被替代的**不删**，只标 `superseded_by`；检索时过滤掉。

---

## 六、证据标注（origin / confidence）

任何「事实」都要能回答：**这条是谁说的？多可信？**

```
chat + speaker=owner → user  0.92
self 转述            → model 0.68
distill 归纳         → model 0.55
hypothesis           → model 0.45
caps / tool          → tool  0.79
research(web)        → web   0.50
```

`confidence < 0.55` 的，注入时挂「·存疑」—— 宁可让我显得不确定，也不要我理直气壮地错。

## 七、真机踩过的坑

### 1. `node:sqlite` 的 `NOT NULL` 列

`uid / kind / text / ts_from / source / created_at` 都是 NOT NULL 且无默认值。
插入时漏一个就 `constraint failed`，而且错误信息不会告诉你缺哪个 —— 用
`PRAGMA table_info(node)` 自己看。

### 2. 路径别写死

第一版把 `/root/...` 写进代码，换机器直接崩。现在全部走 `config.mjs`，
`MG_DB` / `DSH_HOME` / `MEMBRAIN_HOME` 环境变量覆盖。

### 3. 调度器会「假活着」

后台进程靠 `setsid` 拉起，**App/容器一重启就全没了**，而且不会有人告诉你。
必须装看门狗：每 5 分钟 `pgrep`，不在就 `spawn`。

### 4. 日志时区别偷懒

`toLocaleTimeString()` 在容器里可能是 UTC，日志看着像时间倒流。
显式 `process.env.TZ = 'Asia/Shanghai'`。

### 5. 改插件要重启

DSH 插件在启动时装配，改完不重启 = 没改。验证用「影子实例」：
同 profile 在临时端口起一次，带 token 拉首页，200 且 >1000 字节 = 前端包编译通过。

### 6. WebGL 可视化在手机上会骗你

`gl_PointSize` 与 DPR 一叠加，静态看着好，一动就掉帧。
**卡和糊是两个问题**：卡是渲染量大（点数/线段），糊是分辨率低（DPR）——
分开调，别用一个开关同时降。

### 7. Canvas 2D 的 `createLinearGradient` 别放进逐帧循环

一帧建十几个渐变，中端手机直接 5fps。

### 8. `requestAnimationFrame` 链会因异常断掉

任何一帧里抛错，循环就停了，画面定格在上一帧 —— 看起来像「卡死」。
把逐帧的非核心部分（标签、特效）包 `try/catch`，并且**先排下一帧再画**。
